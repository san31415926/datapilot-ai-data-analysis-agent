# DataPilot 失败案例与边界记录

更新时间：2026-07-31

这些记录保留真实开发过程中遇到的失败，不把失败隐藏成“模型偶尔不听话”。每个案例都说明现象、原因、当前处理方式和仍然存在的边界，便于复现、排查和面试时解释。

## 1. `qwen3:4b` 结构化计划不稳定

- **现象**：`qwen3:4b` 可以被 Ollama 检测到，也可以在页面中选择，但针对相同的中文分析问题，不能稳定返回符合 `AnalysisPlan` 契约的 JSON。失败时可能需要修复请求，修复后仍可能无法通过计划校验。
- **原因**：小型本地模型对多步骤工具计划、字段参数和 JSON 约束的遵循能力有限；Qwen3 的思考字段也会消耗输出预算。这个问题不是把提示词再写长就能保证解决的。
- **当前处理**：规划请求使用 `think=false`、ASCII 字段别名和严格的 Pydantic 校验，最多自动修复一次。校验仍然失败时停止执行，不运行任何工具。`qwen2.5:3b` 作为当前稳定验证模型。
- **边界**：不能把“页面可以选择”写成“所有已安装模型都稳定支持 Agent 规划”。

## 2. Kaleido 原生 PNG 导出失败

- **现象**：在当前 Windows 环境中，Plotly `5.24.1` 调用 Kaleido `0.2.1` 进行静态 PNG 导出时，Kaleido 进程可能启动失败并出现 `JSONDecodeError`。
- **原因**：Plotly、Kaleido、Python 版本和 Windows 路径环境之间存在兼容性差异，交互式图表渲染正常不代表静态图片导出一定正常。
- **当前处理**：`export_chart_png()` 先尝试 Plotly/Kaleido；失败后捕获异常，使用 Pillow 生成有效的静态 PNG，并通过结果对象和页面提示标记实际使用的后端。
- **边界**：项目可以提供 PNG 下载，但不能宣称所有机器都能稳定使用 Kaleido 原生 PNG。

## 3. Ollama 服务、模型和请求失败

- **现象**：Ollama 未启动、模型不存在、请求超时、返回非法 JSON 或返回空内容时，本地模型调用不能完成。
- **原因**：模型服务是本机外部依赖，模型文件和服务状态不由 DataPilot 自身保证；结构化计划和报告生成还会受到模型输出格式影响。
- **当前处理**：客户端统一转换为带错误码的中文状态。计划生成失败时不执行工具；报告生成失败时只展示真实工具结果和安全降级说明，不补写模型没有生成的结论。页面也允许在没有 Ollama 时继续查看数据概览和质量检查。
- **边界**：当前版本不是云端高可用服务，也不伪造离线模型已经完成分析。

## 4. 非法字段和危险 SQL 被拒绝

- **现象**：模型计划引用未知字段、写入型 SQL、多语句、注释绕过、外部文件读取、系统表或未知表时，查询不会执行。
- **原因**：自然语言模型可能生成语法正确但越权或不适合当前数据集的查询，不能只相信模型自称“这是安全 SQL”。
- **当前处理**：计划先经过 Pydantic 参数模型、当前数据集字段白名单和 SQLGuard；SQL 只允许单条 `SELECT`，并限制数据源、结果行数、结果大小和执行时间。校验失败会记录结构化错误。
- **边界**：这是单机上传数据的只读分析边界，不等于已经完成企业级数据库权限系统。

## 5. 报告引用不存在的工具步骤

- **现象**：报告模型返回的 `evidence_steps` 如果包含没有成功执行的步骤，报告不会被当作可信报告展示。
- **原因**：模型可能把计划步骤、失败步骤和成功步骤混淆，或者生成与真实执行记录不一致的引用。
- **当前处理**：报告生成器核对引用步骤是否存在且执行成功；不通过时返回安全降级报告，只保留真实工具证据和失败原因，最多进行一次修复请求。
- **边界**：报告中的自然语言仍然需要用户结合表格、SQL、图表和工具记录检查；引用校验不能替代业务人员复核。

## 6. 外置浏览器文件选择器阻断自动上传

- **现象**：使用外置 Edge 做演示时，自动化操作在系统原生文件选择器处返回 `Not allowed`，没有完成“选择样例 CSV -> 上传 -> 展示结果”的自动截图流程。
- **原因**：这是浏览器自动化与 Windows 原生文件选择器之间的权限限制，不足以证明 DataPilot 的上传代码失败。
- **当前处理**：保留真实的 DataPilot 首页截图，不伪造上传后的完整结果截图；样例 CSV 和 XLSX 仍然放在项目 `data/` 目录，用户可以在本机手动选择并完成演示。失败原因记录在本文档中。
- **边界**：当前仓库里的截图只证明首页可以打开，不证明截图中已经展示完整分析结果。

## 已覆盖的输入边界

以下情况已经通过测试或页面逻辑处理：空结果、负值饼图、类别过多、空文件、损坏文件、超限文件、重复字段、缺失值、重复记录、未知表、非法字段、查询超时、模型超时和报告 JSON 不合格。

## 面试复述

可以这样解释：

> 我没有把本地模型或图表依赖当成永远成功的黑盒，而是把结构化计划、SQL、工具结果和报告引用都放在可校验边界内。模型失败时停止或降级，Kaleido 失败时切换 Pillow，并把实际状态展示给用户。这样系统的失败是可观察、可解释、可复现的。
